# 01 — 需求文档（带验收标准的用户故事）

## 史诗级需求

> 作为**银行营销分析师**，我希望有一个一体化的 Web 工具，既能对历史营销数据进行交互式探索分析，又能在新客户到来时通过简单的点选表单快速预测其认购意向，从而辅助营销决策。

---

## US-1：数据概览仪表盘

**作为** 营销分析师
**我希望** 在首页看到一个数据概览仪表盘
**以便** 快速了解数据集的全貌和关键统计量

### 验收标准

- [ ] **AC-1.1**：页面展示数据集的行数、列数、缺失值比例等基础元信息
- [ ] **AC-1.2**：页面展示目标变量（是否认购）的分布（计数 + 比例）
- [ ] **AC-1.3**：页面展示数值型字段的描述性统计（均值、标准差、最小值、最大值、四分位数）
- [ ] **AC-1.4**：页面展示类别型字段的基数（唯一值数量）与频次 Top-N
- [ ] **AC-1.5**：所有指标以卡片/表格形式清晰呈现，同类信息归类

---

## US-2：交互式数据可视化分析

**作为** 营销分析师
**我希望** 能够通过交互式图表探索数据中不同维度与认购结果之间的关系
**以便** 发现影响客户认购的关键因素

### 验收标准

- [ ] **AC-2.1**：支持选择任意数值型字段，绘制直方图/箱线图，并按认购结果分组着色对比
- [ ] **AC-2.2**：支持选择任意类别型字段，绘制柱状图，展示各类别的认购率
- [ ] **AC-2.3**：支持选择两个数值型字段，绘制散点图/相关性热力图
- [ ] **AC-2.4**：图表支持交互（缩放、悬停提示、图例切换）
- [ ] **AC-2.5**：用户可通过侧边栏或下拉框自由切换分析维度和图表类型
- [ ] **AC-2.6**：所有图表有清晰的标题、轴标签、图例

---

## US-3：数据预处理与特征工程

**作为** 数据科学家
**我希望** 系统能自动完成数据清洗与特征工程
**以便** 为模型训练提供高质量的输入特征

### 验收标准

- [ ] **AC-3.1**：自动识别并处理缺失值（数值型用中位数填充、类别型用众数填充）
- [ ] **AC-3.2**：对类别型变量进行编码（One-Hot 或 Label Encoding，按基数自动选择策略）
- [ ] **AC-3.3**：对数值型变量进行标准化/归一化
- [ ] **AC-3.4**：处理异常值（IQR 或 Z-score 方法，可配置）
- [ ] **AC-3.5**：数据按约定比例（默认 8:2）划分为训练集和测试集，分层采样以保证目标变量分布一致
- [ ] **AC-3.6**：预处理流水线可保存为 pickle 文件，供在线预测时复用

---

## US-4：离线模型训练

**作为** 数据科学家
**我希望** 在命令行执行训练脚本时，自动完成多模型训练、评估和选优
**以便** 得到最优模型并部署到预测服务中

### 验收标准

- [ ] **AC-4.1**：`python src/model_train.py` 命令即可触发完整训练流程
- [ ] **AC-4.2**：至少训练 3 种分类模型（如 LogisticRegression、RandomForest、XGBoost）并横向对比
- [ ] **AC-4.3**：以 AUC-ROC、准确率、精确率、召回率、F1-Score 作为评估指标，输出对比表格
- [ ] **AC-4.4**：自动选择 AUC-ROC 最高的模型作为最优模型
- [ ] **AC-4.5**：最优模型及其评估报告保存到 `models/` 目录
- [ ] **AC-4.6**：训练过程中输出关键日志（数据量、训练时间、各模型指标、最终选择）

---

## US-5：在线预测表单

**作为** 营销人员
**我希望** 通过一个点选表单输入客户特征
**以便** 快速得知该客户是否会认购定期存款

### 验收标准

- [ ] **AC-5.1**：表单的每个输入控件与模型输入特征一一对应
- [ ] **AC-5.2**：类别型特征使用下拉选择框（selectbox），数值型特征使用数字输入或滑块
- [ ] **AC-5.3**：每个输入字段旁边有简要说明（中文标签 + 取值范围提示）
- [ ] **AC-5.4**：点击"预测"按钮后，显示预测结果（"会认购" / "不会认购"）及概率置信度
- [ ] **AC-5.5**：预测结果以醒目的视觉样式呈现（如颜色区分、仪表盘样式）
- [ ] **AC-5.6**：表单对必填字段进行前端校验，未填写完整时给出友好提示
- [ ] **AC-5.7**：系统启动时自动加载已训练的最优模型，无需用户手动操作
- [ ] **AC-5.8**：支持重置按钮一键清空表单

---

## US-6：Docker 容器化部署

**作为** 运维工程师
**我希望** 整个应用可以通过 Docker 一键构建和启动
**以便** 在任何支持 Docker 的环境中快速部署

### 验收标准

- [ ] **AC-6.1**：`docker build -t banksys_sy_wangliang .` 可成功构建镜像
- [ ] **AC-6.2**：`docker run -p 8888:8888 banksys_sy_wangliang` 可成功启动容器
- [ ] **AC-6.3**：浏览器访问 `http://localhost:8888` 可正常使用两个功能页面
- [ ] **AC-6.4**：Dockerfile 使用多阶段构建以减小镜像体积（如有必要）
- [ ] **AC-6.5**：提供 `docker-compose.yml` 简化启动流程
- [ ] **AC-6.6**：容器内运行在 `8888` 端口

## US-7：CI/CD 流水线

**作为** 开发团队
**我希望** 每次推送代码时自动触发 CI/CD 流水线
**以便** 确保代码质量和自动化部署

### 验收标准

- [ ] **AC-7.1**：GitHub Actions 工作流在 push / PR 时自动触发
- [ ] **AC-7.2**：CI 阶段包含：ruff 代码检查 → pytest 单元测试
- [ ] **AC-7.3**：CD 阶段包含：Docker 镜像构建并推送至镜像仓库
- [ ] **AC-7.4**：ruff 零告警通过（可配置忽略的规则）
- [ ] **AC-7.5**：pytest 测试覆盖率 ≥ 70%（或所有关键路径有测试覆盖）
- [ ] **AC-7.6**：CI 失败时阻断 CD，不进行部署
- [ ] **AC-7.7**：流水线状态徽章在 README.md 中展示
